# Audit of the tutor tools and pilot operations

Revision 2, November 16, 2026. The [stack comparison](../tutor-stack-audit.md) covers the competing vendors, browser frameworks, PDF parsers and voice transports. This review covers the tools the tutor itself can use, the services that surround them, and what should be measured during implementation. The product and technical specifications linked from [README](../README.md) incorporate these decisions.

## Tutor capabilities

| Capability | Implement first | Alternative and reason to revisit | Evidence required |
|---|---|---|---|
| Search and cite a course | Constrain by owner, lesson/course, published source version and allowed passages before ranking. Compare Postgres text search with the same search fused with BGE vector results. Resolve citations server-side and deep-link to page, cell or row. Preserve exact math notation beside normalized text. | Consider a reranker or hosted embedding model if the baseline misses relevant material on a separate development set. Use a frozen release set to evaluate a final decision. | Score both retrieval recall and whether the final claim is supported. Refuse a wrong-course citation even when its text is identical. Keep normalized data and originals under matching access policies. | Expiring download URLs support convenient sharing, but the pilot promises that future reads stop at deletion. Previously downloaded copies remain on the receiving device. ## Pilot infrastructure

| Area | Decision and alternative | How to catch a bad choice |
|---|---|---|
| Email sign-in | Keep Supabase Auth. Use an invite-only, emailed one-time code and custom SMTP. Some school/work email scanners consume one-click sign-in links before a student opens them. Supabase restricts its default sender to team addresses. Use a local email catcher in development. | Test a real invited external mailbox, pasted/expired code, resend, denied invite, rate limit and post-login return to lesson. [Email templates](https://supabase.com/docs/guides/auth/auth-email-templates) · [SMTP](https://supabase.com/docs/guides/auth/auth-smtp) |
| One-time pilot pass | Create a Stripe-hosted Checkout Session on the backend for each pending purchase. Prefer it over a shared link plus manual email matching. No subscription engine for the four-week pilot. | Test success, unpaid return, duplicate/out-of-order delivery, mistaken identity, refund and manual reconciliation. Use one unique fulfillment record per provider session. [Checkout](https://docs.stripe.com/payments/checkout/how-checkout-works) · [Webhooks](https://docs.stripe.com/webhooks) |
| Background indexing | Use a Postgres job table, atomic claims, expiring leases and fenced publication. Keep parsing independent of the voice service. CSV needs a real parser for quoted delimiters and newlines; notebooks need stable cell locators and safe outputs. | Kill the worker before and after publish; replace/delete while running. Measure upload-to-ready on a mixed course. Evaluate a queue service or layout parser when the measured backlog or source failures justify them. [Postgres locking](https://www.postgresql.org/docs/current/sql-select.html) · [CSV](https://docs.python.org/3/library/csv.html) · [Text extraction](https://pypdf.readthedocs.io/en/stable/user/extract-text.html) |
| Accessibility and UI | Semantic controls, keyboard, labels, captions, focus restoration, motion preference and equivalent chart text/table. Use Playwright Test and axe-core for automated checks, followed by manual assistive-technology tasks and the five-person usability test. | Automated checks cannot establish usability. Verify a learner can stop a share, interrupt, understand the chart and return to the cited text without a narrated tour. [Accessibility testing](https://playwright.dev/docs/accessibility-testing) · [Complex graphics](https://www.w3.org/WAI/tutorials/images/complex/) |
| Deployment and operations | Keep Next.js, one regional long-lived Fastify relay and a separate Python worker. Keep Postgres and media service close to each other. Select a host supporting long-lived WSS, health checks and reconnect during rollout. Use budgets, kill switches and redacted metrics first. | Reconnect during deploy, stop paid work on pause and restore a confirmed board. Benchmark cold and warm paths separately. Count failed and wrong responses. Do not export raw learner content as diagnostic traces. [WebSocket hosting example](https://render.com/docs/websocket) · [Telemetry data handling](https://opentelemetry.io/docs/security/handling-sensitive-data/) |
| Developer tools | Use the pinned Google Live and Supabase Postgres skills. Playwright Test handles regression; its CLI is optional. Local Supabase and synthetic CI remain the normal development path. The lead agent can delegate a bounded, independent feasibility test. | Build once from a clean checkout. Exercise normal upload → cite → chart; separate offline, live-provider, real-device and human evidence. [Build sequence](08-build.md) · [First stack review](../tutor-stack-audit.md) |

## Measurements made for this revision

The following are small engineering probes on synthetic inputs. They establish implementation choices and regression cases; their timings exclude a browser, network, retrieval, audio or a model.

- **Histograms.** One 100,000-row column of integer scores, six explicit edges [0,8,16,24,32,40], Node 24.22.1. Seven warm-ups and 101 measured repetitions. Direct counting using a binary edge search took **2.22 ms median, 3.48 ms p95**. A query on an already sorted Float64Array took **0.0043 ms median, 0.0075 ms p95**, with **6.95 ms median** to build the sorted array. Both returned [19623,19557,19504,19409,21907], confirmed with NumPy, and agreed for six additional edge sets. Start with direct counting and profile the actual browser. A cached query alone is an unfair comparison for a first chart.
- **Regression.** For x = 1,000,000,000 plus [0,1,2,3] and y = [5,7,9,11], JavaScript's raw-sums denominator rounded to zero. Centered sums gave slope 2, independently checked with SciPy, and a prediction of 10 at x = 1,000,000,002.5. This case is now a required release test.
- **Pointer mapping.** On a 1600 × 900 frame shown in an 800 × 600 contain-fit view, the top 75 pixels are outside the content. A center click maps to (0.5,0.5); a click at y = 40 must be ignored. Three deterministic mapping assertions passed. Browser zoom, capture and the real permission UI still need device tests.
- **Earlier measurements.** The [first stack review](../tutor-stack-audit.md) measured two PDF extractors on 60 synthetic pages. The headless browser attempt in that review failed at startup under the environment's socket restriction. No comparative browser or production latency conclusion follows from it.

Official docs and these probes cover different questions. Live provider access and cost, SMTP deliverability at the pilot institution, paid fulfillment, deployment, learner outcomes, accessibility with actual users, and an actual paired Jupyter edit remain implementation or field checks. Neither the skill setup nor a mock integration closes those gates.
