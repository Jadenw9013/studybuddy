# Staging and incident procedures

Use separate Supabase projects, SMTP senders, private buckets, Stripe test products and Gemini billing projects for development, staging and production. Production requires HTTPS, a long-lived WSS relay and private worker connectivity. Route `/api` and `/live` to the API and `/companion` to its scoped socket. Never publish the local database. Set `API_HOST=0.0.0.0` only inside the private container network.

The provider and billing switches default off. Set `PAID_CALLS_ENABLED=false` and `ENABLE_LIVE=false` to stop paid calls. Set `ENABLE_ILLUSTRATIONS=false` to disable new image requests; restart the API to abort pending image transports. Set `ENABLE_COMPANION=false` to prevent new pairs; restart the API to close existing sockets. Pause releases microphone and capture and revokes notebook access and pending illustrations. Keep text, sources and practice available during a voice failure. A relay rollout must be tested with an active real lesson before pilot launch.

Before enabling paid access, confirm invited external email OTP delivery with custom SMTP, provider model access and terms, a current unit-price table, a 20-minute metered lesson and the $7.60 per-pass projection. Missing configuration and fixture tests do not establish live integration. Stripe Checkout is created only by an authenticated backend request and remains disabled by default. Verify signed webhook fulfillment and refund policy in test mode before enabling billing.

Deletion revokes application reads immediately and clears source-dependent copied lesson content. Previously received bytes cannot be recalled. Hosting backup expiry and provider retention must be established before inviting external learners. Course/account purge completion and backup erasure require the separate staging drill; the response distinguishes revocation from pending purge. Do not promise immediate third-party erasure.

For backup/restore, export the private Postgres database and storage manifest to an approved encrypted destination using project operations credentials. Restore into an isolated staging project, run `pnpm db:migrate`, run RLS tests with two synthetic accounts, and check source locators and board revisions. This repository does not start a backup service or choose a retention policy without an operated deployment.

Operational logs must contain only allowlisted event names, timestamps, opaque lesson/action IDs, revisions, result codes, token counts and latency. Do not log uploaded text, user questions, emails, pairing URLs, provider secrets or raw audio/screens. Playwright traces use original synthetic fixtures only. Live metrics must distinguish first packet, scheduled audio proxy, human-marked useful audio, render callback proxy and observed correct paint.
