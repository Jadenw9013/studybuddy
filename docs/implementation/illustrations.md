# Optional FLUX illustrations

Implemented November 19, 2026, on the existing revision-2 handoff. The optional illustration candidate is now klein 9B for the hosted BFL API, as requested during configuration review. The canonical handoff files remain unchanged.

The lesson's **Optional illustrations → Create an illustration** controls require an explicit learner Generate action with a description, title and pedagogical purpose. The form stays collapsed until requested so it does not displace the chart and practice task. It requests one 768×768 conceptual image without reference uploads. The tutor model does not autonomously start paid image generation. The asynchronous job uses the versioned `illustration.generate` action envelope and the same owner/course, epoch, board revision and idempotency checks as other mutations. A duplicate request returns its recorded result; a changed payload conflicts. Image IDs are unique across the owner's lessons, including removed lessons.

The server keeps the key private, submits once, polls the provider's returned task URL, and downloads a bounded PNG/JPEG/WebP from BFL's documented delivery namespace. All requests are HTTPS with explicit host/path checks, no redirects, a 90-second deadline, a maximum of 180 polls, bounded response bodies and raster header checks. Authentication is never forwarded to image downloads. No provider URL, key, raw provider error or fingerprint is rendered in the browser. The UI renders only an authenticated content path for its current lesson and image.

Images live in the existing private `course-originals` bucket, below owner/course/illustrations/lesson/image, or a private local directory for injected-provider tests. Migration `202611190004_illustrations.sql` adds normalized metadata with forced RLS, composite scope foreign keys and API-role-only privileges. Pending metadata persists before network work; only terminal receipts enter the immutable action ledger. Storage publication holds the owner transaction so a delete cannot complete before a late upload. A fresh authorization/status check precedes and follows image reads.

Pause/interruption, logout, board changes, source deletion and lesson/course/account deletion revoke pending work. Ready illustrations remain separate from the verified chart; they are clearly labeled **AI-generated illustration**. Late results are discarded. Cancel cannot revoke work already accepted by BFL, so ambiguous charges retain a conservative provision and block further paid admission until reconciliation. Removing an image revokes new reads, scrubs its prompt/title/purpose and queues byte purge. A hash preserves retry identity after plaintext removal. Deleting course content cannot reset the daily request counter.

The cost hold uses the same per-pass ledger as text and voice. Defaults are 10 images per UTC day, the existing $7.60 pass ceiling and an operator-visible versioned estimate of $0.015 for one klein9B image in the first megapixel. Price source: [BFL pricing](https://bfl.ai/pricing?category=flux.2), reviewed November 19. This estimate is not a provider invoice. Explicit rejection before task acceptance releases the hold; unknown outcomes do not silently refund it. If returned dimensions exceed the first-megapixel price bound, cost remains unknown rather than undercounting.
